# 2026-09-17 工作记录

## 修正"调整文档格式"两处越界改格式

### 需求
"变更文章首行总标题"中字体/字号均为"不变更"，但点"调整文档格式"后首行标题
格式仍被改；且表格内文字段落格式被统一成与正文相同。要求：不变更的项不得改动，
表格文字不随正文变化。

### 根因一：首行总标题 —— 套新建样式时丢了原字体字号
`set_document_format.set_main_title_format()` 无条件把第 1 段套到新建的
`MainTitle` 样式上。该样式是 `Styles.Add` 新建的，字体字号继承文档默认值
（如宋体五号），于是段落原有字体字号被样式默认值覆盖 → "选了不变更也被改"。
另外 `MainTitle` 基于 Normal，后续 `set_content_style` 改 Normal 的首行缩进
会连带让总标题多出"首行缩进2字符"。

**改法**：font/font_size 为 None（不变更）时，先读段落**处理前**的有效字体
（`get_effective_font_names`）与字号（`get_effective_font_size`），以原值写入
样式；缩进一律按原值钉住（取不到按 0），避免继承 Normal 后续被改写。
加粗/居中/段前段后 0.5 行仍按参数执行（属总标题固有格式）。

### 根因二：表格文字被正文"同化"
`set_content_style()` 改的是「正文」/Normal **样式本身**，而表格内段落大多与
正文共用该样式 → 表格文字的字号、对齐、缩进跟着变。
另 `set_content_format()` 里 `paragraph_style.Font.Name = font` 也是改**样式
对象**（不是段落直接格式），同样会污染表格内段落。

**改法**：
1. `set_content_format()` 的字体分支改为写段落**直接格式**
   （`paragraph.Range.Font.Name` + `NameFarEast`），与字号分支一致，
   不再动共享样式。
2. 新增 `snapshot_table_paragraph_format()` / `restore_table_paragraph_format()`：
   改「正文」样式前快照表格内段落的有效字体/字号/缩进/对齐，
   改完以直接格式写回（直接格式优先于样式）。调用点用 try/finally 包裹
   `set_content_style`，快照点放在 `set_content_format` **之前**。

### 顺序上的关键点
快照必须在 `set_images_and_tables` / `set_tables_auto_adjust_and_align`
**之后**取：那一步有意把表头行居中、表格缩进归零，快照取的是这些"期望值"，
还原时不会把它们退回去。实测位置（main_form `_on_format_adjust`）：
页边距 → 页码 → 总标题 → 图片表格 → 【正文格式 + 快照/还原】→ 章节标题 →
表格上下间隔。

### 顺带修的隐患
`event_handlers.py` 的 `button_format_adjust_click()`（旧版路径，按钮实际绑定
`main_form._on_format_adjust`）把字面字符串"不变更"直接传给
`set_main_title_format`，会被当成字体名写进 Word。已改为先转 None。

### 改动文件
- `set_document_format.py`：`set_main_title_format` 重写；新增两个表格格式保护
  方法；`set_content_format` 字体分支改直接格式；补充 word_constants 导入。
- `main_form.py`：`_on_format_adjust` 中加快照/还原包裹。
- `event_handlers.py`：同上 + "不变更" → None。

四个模块 `py_compile` 通过；`SetDocumentFormat` 可正常 import，
新方法签名正确（`snapshot_table_paragraph_format(self)` /
`restore_table_paragraph_format(self, snapshots)`）。
