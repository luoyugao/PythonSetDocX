# 2026-09-16 工作记录

## 修正"转自动序号"：转换前后序号形式保持一致

### 需求
单级与多级序号转换后，应与转换前的形式一样（中文序号、阿拉伯数字等各体系均须保持原形式）。

### 问题根因（两处，均在 `auto_numbering.py`）

1. **样式信息在检测阶段被压扁**
   `_classify_to_style()` 把 20 多种序号体系（天干、地支、字母、罗马、希腊、
   圈号字母、全角数字…）全部归并成只有 3 种输出：`"一."`(中文) / `"1."`(阿拉伯) /
   `"①"`(圈号)。`_number_format_for_style()` 再据此只产出三种格式。
   → 天干"甲、"被渲染成"1."，罗马"Ⅳ."变"4."，全角"１．"变半角"1." …形式全丢。

2. **多级序号强制改写为阿拉伯数字**
   `_ensure_multilevel_template()` 中 `if lvl in cascade_levels and ns != 0:`
   把级联链路上所有非阿拉伯体系强制改成 `"%N. "` + ArabicStyle。
   → "一.1"这类多级形式被破坏。

### 修改内容

**`word_constants.py`** — 补充 WdListNumberStyle 常量：
`UppercaseRoman=1`/`LowercaseRoman=2`/`UppercaseLetter=3`/`LowercaseLetter=4`/
`ArabicFullWidth=14`/`Zodiac1=30`/`Zodiac2=31`/`Zodiac3=32`/
`SimpChinNum1=37`/`SimpChinNum2=38`/`UppercaseGreek=61`/`LowercaseGreek=60`。
（`wdListNumberStyleArabic=0` 原已存在，未重复定义。）

**`auto_numbering.py`** — 让"完整形式"一路传递到建表：
- `_classify_to_style()` 改为返回**体系标识**而非压扁的样式名，
  形如 `"chinese_num:sep"` / `"arabic:paren"` / `"arabic:rparen"` / `'①'`。
  后缀 `:sep`/`:paren`/`:rparen` 承载分隔符与括号形式。
- 新增 `_STYLE_MAP`：体系名 → (NumberStyle, 能否级联)。
- 新增 `_resolve_style()`、`_detect_style_base()`（识别全角数字 →
  `arabic_full`）、`_style_cannot_cascade()`。
- 新增哨兵 `_SEP_PAREN_PAIRED`，区分成对括号 `(1)` 与仅右括号 `3)`。
  `_detect_paren_form()` 传该哨兵，避免给 `3)` 补上不存在的左括号。
- 重写 `_number_format_for_style()`：按体系还原真实 NumberStyle 与括号/分隔符。
- `_ensure_multilevel_template()` 去掉"强制阿拉伯数字"，改为保留各级原形式；
  仅圈号（字符集无 0-9）无法作为 `%N` 级联时才降级为数字兜底。

### 关键结论（Word 行为）
- Word 渲染多级编号 `%1` 时采用**被引用级别自身**的 NumberStyle，
  所以"一.1"可以直接级联，无需把上级改写成阿拉伯数字。
- 圈号体系（①、Ⓐ、ⓐ）字符集里没有数字形，不能作为 `%N` 参与级联，
  这是唯一必须降级的体系。
- 天干/地支对应 `wdListNumberStyleZodiac1/Zodiac2`。
